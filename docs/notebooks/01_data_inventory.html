01 · Data inventory¶

Question¶

Which public EERIE simulations provide the fields needed to study the winter NAO and extremes over the UK and Ireland (RX1day, TXx, R95p), and can they actually be read? The fields are daily pr, psl, tas, tasmax and monthly psl, tas, ideally on the common 0.25° grid (gr025).

Data¶

Public sources only, read over HTTPS with no login:

  • DKRZ km-scale cloud (eerie.cloud.dkrz.de): dataset list at /datasets, one STAC item per dataset, data as Zarr.
  • eerie-project intake catalogues on GitHub (eerie.yaml), which also carry the JASMIN and CEDA (BADC) file listings for the Met Office HadGEM3-GC5 runs.
  • JASMIN public (gws-access.jasmin.ac.uk/public/eerie) and the CEDA archive (dap.ceda.ac.uk), probed for anonymous access.

Method¶

  1. List every dataset id on the DKRZ cloud and keep the atmosphere collections of the coupled models.
  2. Read each dataset's STAC item for its variables and period.
  3. Map each model's native names onto the six target fields (eerie_uk.catalogue.VARIABLE_MAP), e.g. IFS tprate/mmsl/mean2t/mx2t24, and ICON daily-maximum tas for tasmax.
  4. A run qualifies when all six fields are served.
  5. Summarise the JASMIN/CEDA listings the same way and test one file per server.
  6. Open one winter of daily psl over the UK/Ireland box to prove end-to-end access.

Listing is not access. Each test below opens a collection and loads one global time step, through the raw-chunk endpoint (kerchunk) and, for IFS-FESOM2-SR, also the server-side decoded one (zarr).

Limitations¶

  • The inventory reads STAC metadata; only the collections in the read-test table were actually read, and only one winter of one variable was downloaded.
  • IFS-FESOM2-SR chunks are raw GRIB whose ECMWF local section current ecCodes cannot parse; eerie_uk.grib drops that section before decoding. Values look physical but have not been compared against an independent reader. The server-side decoded endpoint (zarr) returned HTTP 500 and is not used.
  • IFS-FESOM2-SR precipitation (tprate) is in m s⁻¹, ICON pr in kg m⁻² s⁻¹; units must be harmonised before any comparison.
  • The DKRZ server holds raw daily chunks of the whole globe (about 4 MB per day per variable), so a UK box still pulls global fields; long records will be slow.
  • Native variable names differ between models and the mapping is hand-written; units (e.g. tprate) still need checking before any analysis.
  • HadGEM3-GC5, the cleanest resolution ladder (N96-ORCA1 / N216-ORCA025 / N640-ORCA12), is listed in the public JASMIN catalogue but its files are not downloadable without a login; DKRZ and CEDA carry monthly fields only, and DKRZ has no psl.
  • No same-model pair of eddy-rich and coarser-ocean runs could be downloaded at daily frequency, so any contrast across models mixes ocean resolution with model differences.
  • The catalogue is live and changes; this is a snapshot from the run date.
