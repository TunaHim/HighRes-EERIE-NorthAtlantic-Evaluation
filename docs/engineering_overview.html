2. Why so much is streamed and so little is kept

The DKRZ server stores each day as one file for the whole globe. Whatever region you ask for, the whole globe comes over the internet. The pipeline cuts out the North Atlantic or north-west Europe box in memory, saves only that, and throws the rest away.

4. How the code is organised and checked

SafeguardWhat it does
87 offline tests (pytest)Each calculation is tested on small made-up data with a known answer: the EOF sign convention, the winter-year rule, R95p on a toy series, the GRIB fix, unit conversion, resuming a failed download, significance testing.
Frozen methods (docs/methods.md)Definitions fixed before any result was produced, so results cannot quietly steer the method.
Data checks in the notebooksEvery analysis starts by checking that files are complete, time axes are correct and values are physical.
Version control (git)Each commit describes one step; the history shows how the work developed.
Reproducible environmentenvironment.yml rebuilds the same Python setup on any machine.

5. Scaling up: what changes and what stays

One laptop, an ordinary connection; the network is the bottleneck. The yearly file is the unit of work and the analysis does not care where the data came from, so growth changes the data layer, not the science code.

6. In one sentence

Public climate-model output from a remote data centre is discovered automatically, read without downloading whole files to disk, decoded, harmonised and cut to the region of interest year by year with retries and safeguards, stored as a small tested archive, and analysed by a library whose functions do not care which model, reanalysis or observation dataset they receive, which is what makes the same pipeline usable for more members, CMIP6 and CMIP7.
